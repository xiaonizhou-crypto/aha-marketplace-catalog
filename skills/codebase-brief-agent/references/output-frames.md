# Output Frames

Use this file only to decide which brief type best matches the request.

## Executive Brief
Choose this when the user is asking:
- what this repo does
- explain the system to me
- help me understand this project
- give me a founder / PM / operator summary

Best when the user needs leverage, not implementation detail.

### Shape
- Product summary
- Architecture snapshot
- Key modules
- Main flows
- Risks
- Next actions

## Change Map
Choose this when the user is asking:
- where do I edit X
- how would I add Y
- what files should I change
- what breaks if I touch this area

### Shape
- Requested change
- Likely files to edit
- Adjacent dependencies
- Test checklist
- Risk notes

## Handoff Brief
Choose this when the user is asking:
- onboard me to this repo
- help me hand this to another person
- review what matters here
- what should a new owner read first

### Shape
- Read first
- System boundaries
- Known debt / gotchas
- Ownership hotspots
- First-week orientation plan

## Style rules
- Keep language plain and practical
- Prefer filenames over abstractions
- Prefer actionability over completeness
- Keep each section scannable
