# Signal Rules

Use this file when ranking public updates is ambiguous.

## High signal
Mark as high signal when an update has at least one of these properties:
- changes product direction for a meaningful category
- reduces setup friction or cost in a way that broadens adoption
- reflects a credible shift from demo to usable product
- shows strong founder, developer, or user demand from multiple sources
- affects distribution, GTM, or monetization, not just features

## Medium signal
Mark as medium signal when:
- the update is interesting but impact is still unclear
- a repo or product is growing, but staying in niche territory
- the post has useful insight, but not category-level implications

## Low signal / skip
Mark as low signal when:
- it is mostly engagement bait
- it repeats a familiar claim without new evidence
- it is hype around visuals without practical consequence
- it is a tiny feature with little leverage

## Ranking rule
Prefer fewer, sharper items. A digest with 3 useful signals is better than one with 15 weak bullets.

## Why-it-matters rule
Always explain impact in practical terms:
- does it change cost
- does it change speed
- does it change capability
- does it change adoption
- does it change workflow quality

## Confidence rule
- High: multiple signals align, or the evidence is direct and concrete
- Medium: plausible but still early
- Low: thin evidence or mostly anecdotal
